# Marosim — каталог и прямые сообщения поставщикам

Production-shaped validation MVP маркетплейса услуг для свадеб, культурных мероприятий, тренингов и корпоративных событий в Узбекистане.

## Что уже можно проверить как пользователь

- Клиент: фильтрует каталог, видит свежесть данных и проверку поставщика, сохраняет подходящие предложения и сразу пишет поставщику.
- Планировщик клиента: закрывает обязательные категории свадебного чек-листа и видит сводный бюджет.
- Поставщик: получает целевые сообщения, отвечает клиентам в общем чате и управляет списком предложений.
- Поставщик/контент-менеджер: скачивает Excel-шаблон с примерами, загружает прайс, видит ошибки до записи и создает только черновики.
- Администратор: видит поставщиков, активных пользователей, онлайн, новые диалоги и скорость первого ответа по периоду; модерирует карточки, блокирует поставщиков с обязательной причиной и видит аудит действий.
- Мобильное приложение: `/mobile_app` сразу открывает клиентский поиск и быстрые категории; `/mobile_app/supplier` даёт поставщику отдельный рабочий старт. Это responsive web/PWA без второй кодовой базы и отдельной сборки магазина приложений.

Защитные правила MVP: сообщение не выдается за бронь, подтверждение наличия или оплату; малые выборки не превращаются в «рейтинг ответа»; импорт не публикуется автоматически; внешняя CRM не нужна.

## Локальный запуск

Требуется Node.js 20.9+ и pnpm 11.19.0.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://localhost:3000`. По умолчанию работает `demo`-режим: данные сохраняются в `localStorage`, поэтому продукт можно целиком проверить без внешних сервисов. Сброс состояния и роли доступны на `/demo`.

Вход через Google подтверждается сразу. Для входа по телефону используется код `1234`; реальная отправка SMS пока не подключена. После авторизации новый пользователь выбирает один из двух профилей: поиск для события или размещение услуг и товаров. Роль администратора отсутствует в публичном выборе и доступна сотрудникам только по внутренней ссылке `/login?role=admin`.

```bash
pnpm lint

pnpm build
```

Проверка здоровья приложения: `GET /api/health`. Excel-шаблон: `GET /api/templates/services`.

## Production data path

В `supabase/migrations` находится схема PostgreSQL с Row Level Security. Она разделяет данные клиента, поставщика и администратора; публично читает только опубликованные услуги активных поставщиков. `supabase/seed.sql` загружает справочник категорий, а `pnpm seed:auth` создает тестовые учетные записи после настройки переменных из `.env.example`.

До подключения Supabase интерфейс намеренно остается в проверяемом demo-режиме. Это не маскируется под production-бэкенд.

## Развертывание

CI проверяет lint, типы, unit-, browser-тесты и сборку. Текущее изолированное окружение запускается отдельным пользовательским `systemd`-сервисом на `127.0.0.1:3001` и доступно через Cloudflare Tunnel по адресу `https://marosim.fom-analytics.uz`. Воспроизводимая инструкция и вариант для Docker находятся в [deploy/README.md](deploy/README.md).

## Очередь развития

1. Каталог и прямой чат с поставщиком: текущий проверяемый срез.
2. Подтверждаемая доступность, история взаимодействия и антифрод-критерии отзывов.
3. Бронирование и платежи только после отдельного юридического и операционного решения.
4. Расширение от свадеб к тренингам, тимбилдингам и другим business events.

У этапов намеренно нет сроков: это порядок проверки ценности, а не календарное обещание.
