# Marosim — каталог предложений для событий

Production-shaped validation MVP маркетплейса услуг для свадеб, культурных мероприятий, тренингов и корпоративных событий в Узбекистане.

## Что уже можно проверить как пользователь

- Клиент: фильтрует 100 реальных предложений, открывает страницу автора и исходное объявление, сохраняет подходящие варианты. Если нажать «Сохранить» без входа, Маросим попросит авторизоваться, а затем добавит предложение в «Сохранённые».
- Расчёт мероприятия: клиент указывает дату, город и количество людей, редактирует строки. Для внешнего объявления Marosim готовит текст запроса, который нужно отправить автору через исходную площадку; автоматической доставки нет. Версионный расчёт внутри чата остаётся для собственных предложений автора, когда они будут опубликованы в Marosim.
- Страница предложения: показывает исходное описание, фото с увеличением, автора, источник и дату просмотра. Неподтверждённые цена, наличие, скорость ответа, пакеты и биографические сведения не придумываются. Одна исходная карточка содержит ссылку на YouTube-видео автора.
- Планировщик клиента: закрывает обязательные категории свадебного чек-листа и видит сводный бюджет.
- Автор предложения: может загрузить собственные предложения и открыть черновик в приватном предпросмотре. Для авторов внешних объявлений пока действует переход на источник; значок у имени позволяет обратиться за подтверждением страницы через Telegram.
- Автор предложения/контент-менеджер: скачивает Excel-шаблон с двуязычными примерами, заполняет название и короткое описание на русском и узбекском, загружает прайс, видит ошибки до записи и создает только черновики.
- Администратор: видит 100 SKU и 87 авторов из открытых источников; счётчики посетителей и чатов пока относятся только к его браузеру, не ко всей платформе.
- Каталог: 95 доступных объявлений OLX.uz и 5 предложений с официальных сайтов, 100 локальных облегчённых фотографий, 18 из 19 детальных категорий. Для каждого предложения сохранены ссылка, автор, дата просмотра и источник изображения в [манифесте](docs/research/olx-verified-100.json).
- Мобильное приложение: `/mobile_app` сразу открывает клиентский поиск и быстрые категории; `/mobile_app/supplier` даёт автору предложения отдельный рабочий старт. Это responsive web/PWA без второй кодовой базы и отдельной сборки магазина приложений.
- Языки: переключатель `O‘Z | RU` доступен в шапке и в мобильном приложении, выбор сохраняется в cookie. Системный интерфейс и справочники локализованы; исходные описания внешних предложений пока показываются на языке первоисточника. Собственные новые карточки требуют русскую и узбекскую версии. Технические идентификаторы `supplier` сохранены для совместимости данных.
- Тип события: отдельный фильтр каталога дополняет категорию и покрывает свадьбу, никах, день рождения, детский праздник, корпоратив, тимбилдинг, HoReCa и другое семейное событие.

Защитные правила MVP: сообщение и предварительный расчёт не выдаются за бронь, договор, подтверждение наличия или оплату; версии расчёта не перезаписываются; малые выборки не превращаются в «рейтинг ответа»; импорт не публикуется автоматически; внешняя CRM не нужна.

В нижнем колонтитуле доступны примерный номер поддержки и [условия использования](app/offer/page.tsx). Платная публичная оферта не активируется, пока не указаны владелец, реквизиты, тарифы, оплата и возвраты.

## Локальный запуск

Требуется Node.js 20.9+ и pnpm 11.19.0.

Для автономного показа на этом компьютере дважды нажмите `START-MAROSIM-LOCAL.bat`. Скрипт при необходимости обновит production-сборку, запустит её в фоне и выведет локальные ссылки. Каталог и фотографии работают без интернета, но переход к автору на внешней площадке требует подключения. Остановить локальную версию можно через `STOP-MAROSIM-LOCAL.bat`. Краткий ранбук и все адреса: [docs/LOCAL-DEMO.md](docs/LOCAL-DEMO.md).

```bash
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://localhost:3000`. Вход и действия пользователя пока сохраняются только в `localStorage` этого браузера; общий чат и статистика между устройствами без серверной БД не работают. Сброс локального состояния доступен на `/demo`.

Вход через Google подтверждается сразу. Для входа по телефону используется код `1234`; реальная отправка SMS пока не подключена. После авторизации новый пользователь выбирает один из двух профилей: поиск для события или размещение услуг и товаров. Роль администратора отсутствует в публичном выборе и доступна сотрудникам только по внутренней ссылке `/login?role=admin`.

## Production data path

В `supabase/migrations` находится схема PostgreSQL с Row Level Security. Она разделяет данные клиента, автора предложения и администратора; публично читает только опубликованные предложения активных авторов. В коде роль автора по-прежнему называется `supplier`, чтобы не ломать схему и маршруты. `supabase/seed.sql` загружает справочник категорий, а `pnpm seed:auth` создает тестовые учетные записи после настройки переменных из `.env.example`.

До подключения Supabase интерфейс намеренно остается в проверяемом demo-режиме. Это не маскируется под production-бэкенд.

## Развертывание

CI проверяет lint, типы, unit-, browser-тесты и сборку. Текущее изолированное окружение запускается отдельным пользовательским `systemd`-сервисом на `127.0.0.1:3001` и доступно через Cloudflare Tunnel по адресу `https://marosim.fom-analytics.uz`. Дополнительная статическая сборка `pnpm build:sites` публикует тот же интерфейс в OpenAI Sites; её проект и публичный каталог зафиксированы в `.openai/hosting.json`. Воспроизводимая инструкция и вариант для Docker находятся в [deploy/README.md](deploy/README.md).

## Очередь развития

1. Каталог и прямой чат с автором предложения: текущий проверяемый срез.
2. Подтверждаемая доступность, история взаимодействия и антифрод-критерии отзывов.
3. Бронирование и платежи только после отдельного юридического и операционного решения.
4. Расширение от свадеб к тренингам, тимбилдингам и другим business events.

У этапов намеренно нет сроков: это порядок проверки ценности, а не календарное обещание.
