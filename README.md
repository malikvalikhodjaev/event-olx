# EventHub UZ — Каталог и заявки

Production-shaped validation MVP маркетплейса услуг для свадеб, культурных мероприятий, тренингов и корпоративных событий в Узбекистане.

## Что уже можно проверить как пользователь

- Клиент: фильтрует каталог, видит свежесть данных и проверку поставщика, собирает shortlist, отправляет нормализованную заявку и отслеживает статус.
- Планировщик клиента: закрывает обязательные категории свадебного чек-листа и видит сводный бюджет.
- Поставщик: видит целевые заявки, фиксирует просмотр и первый ответ, контролирует список услуг и загрузку по датам.
- Поставщик/контент-менеджер: скачивает Excel-шаблон с примерами, загружает прайс, видит ошибки до записи и создает только черновики.
- Администратор: одобряет, возвращает или скрывает карточку, блокирует поставщика с обязательной причиной и видит аудит действий.
- Мобильный пользователь: получает responsive web/PWA, которую можно установить с браузера без отдельной сборки магазина приложений.

Защитные правила MVP: заявка не выдается за бронь или оплату; малые выборки не превращаются в «рейтинг ответа»; импорт не публикуется автоматически; внешняя CRM не нужна.

## Локальный запуск

Требуется Node.js 20.9+ и pnpm 11.19.0.

```bash
pnpm install --frozen-lockfile
pnpm dev
```

Откройте `http://localhost:3000`. По умолчанию работает `demo`-режим: данные сохраняются в `localStorage`, поэтому продукт можно целиком проверить без внешних сервисов. Сброс состояния и роли доступны на `/demo`.

Все демонстрационные учетные записи используют пароль `EventHub-Demo-2026!`:

| Роль | Email |
|---|---|
| Клиент | `client@eventhub.local` |
| Планировщик клиента | `planner@eventhub.local` |
| Поставщик | `supplier@eventhub.local` |
| Планировщик поставщика | `supplier-planner@eventhub.local` |
| Администратор | `admin@eventhub.local` |

В текущем demo-срезе вход имитируется переключателем ролей: это позволяет провести приемку сценариев без ложного ощущения production-аутентификации.

## Проверки

```bash
pnpm lint

pnpm build
pnpm exec playwright install chromium
pnpm test:e2e
```

Проверка здоровья приложения: `GET /api/health`. Excel-шаблон: `GET /api/templates/services`.

## Production data path

В `supabase/migrations` находится схема PostgreSQL с Row Level Security. Она разделяет данные клиента, поставщика и администратора; публично читает только опубликованные услуги активных поставщиков. `supabase/seed.sql` загружает справочник категорий, а `pnpm seed:auth` создает тестовые учетные записи после настройки переменных из `.env.example`.

До подключения Supabase интерфейс намеренно остается в проверяемом demo-режиме. Это не маскируется под production-бэкенд.

## Развертывание

CI проверяет lint, типы, unit-, browser-тесты и сборку. После push в `main` workflow публикует изолированный контейнер в GitHub Container Registry. Инструкция безопасного запуска в выделенном dev-space: [deploy/README.md](deploy/README.md).

Фактическая внешняя публикация требует только четырех данных от владельца пространства: SSH-доступ, путь каталога, доступный локальный порт и внешний HTTPS URL/reverse-proxy route.

## Очередь развития

1. Каталог и заявки: текущий проверяемый срез.
2. Подтверждаемая доступность, история взаимодействия и антифрод-критерии отзывов.
3. Бронирование и платежи только после отдельного юридического и операционного решения.
4. Расширение от свадеб к тренингам, тимбилдингам и другим business events.

У этапов намеренно нет сроков: это порядок проверки ценности, а не календарное обещание.
