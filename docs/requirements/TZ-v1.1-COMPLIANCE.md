# Соответствие Marosim требованиям ТЗ 1.1

Дата сверки: 5 сентября 2026 года. Источники: `docs/source/TZ_EventHub_UZ.docx` и `docs/source/TZ_EventHub_UZ_Prilozhenie1.docx`, редакции 1.1. Старые названия продукта в источниках считаются историческим контекстом; в продукте используется Marosim.

| Требование ТЗ 1.1 | Состояние MVP | Решение |
|---|---|---|
| Веб и мобильный доступ | Соответствует по пользовательскому результату | Responsive PWA работает в браузере и устанавливается как «Мобильное приложение». Отдельные native iOS/Android клиенты сознательно отложены. |
| Русский и узбекский на старте | Частично соответствует | Интерфейс и справочники переключаются RU/O‘Z. Для новых карточек импорт требует оба языка. У большинства 100 прежних seed-SKU пока русский fallback; нужна контентная миграция до production-публикации. |
| Каталог и фильтры | Соответствует текущему срезу | Есть поиск, функциональная категория, формат получения, город и независимый фильтр по восьми типам события. |
| Основные и дополнительные категории | Соответствует по охвату с другой навигацией | Вместо плоского списка используются три понятных раздела и 19 детальных категорий, включая «Предложение руки и сердца» и «Подарки и полиграфия». Это намеренное продуктовое уточнение. |
| Бесплатное размещение во всех категориях | Зафиксировано, монетизация не подключена | Ограничений по бесплатным категориям нет; платные функции не заявляются. |
| Полная карточка предложения | Реализовано для проверяемых примеров | Есть автор, описание, цена «от», пакеты, особенности категории, территория, доступность, свежесть, профиль исполнителя и увеличиваемое портфолио; поддерживается ссылка YouTube. |
| Медиа-минимумы по категориям | Следующий обязательный шаг | Модель медиа есть, но публикационный валидатор минимумов ещё не реализован. До него модератор не должен считать карточку формально полной. |
| Видео для живых выступлений | Следующий обязательный шаг | В production-проверке публикации потребуется минимум одно видео; 2–3 и свежесть материала остаются рекомендациями. |
| Календарь доступности | Частично соответствует | Показывается статус и дата подтверждения доступности. Полноценная занятость по датам ещё не реализована. |
| Заявка, чат и ручное подтверждение | Соответствует принятому упрощению | Клиент сразу открывает чат или отправляет структурированный предварительный расчёт. Автор возвращает пересчёт новой версией; история сохраняется. Чат и расчёт не считаются бронью, договором или оплатой. |
| Отзывы только после завершённой сделки | Не реализовано намеренно | Публичного рейтинга нет до появления подтверждаемого статуса сделки и антифрод-правил. |
| Автоматический статус «Топ» | Не реализовано намеренно | Нельзя покупать или назначать вручную. Появится после production-данных по завершённым сделкам, успешным услугам и сроку после верификации. |
| Документы и подтверждение личности | Частично | В интерфейсе есть признак проверки автора, но production-процесс загрузки, хранения и проверки документов ещё не подключён. |
| Администрирование и модерация | Соответствует MVP | Внутренний вход, сводка по пользователям и SKU, модерация, блокировка с причиной и аудит действий. |
| Самостоятельная экосистема без CRM | Соответствует прямому решению владельца | Внешняя CRM не требуется. Массовое создание черновиков выполняется через двуязычный Excel-шаблон. |
| Бронирование и платежи | Вне текущего среза | Требуют отдельного юридического и операционного решения; интерфейс не имитирует их наличие. |

Главный остаточный риск соответствия — не архитектура, а качество контента: прежний демонстрационный каталог нужно перевести на узбекский и проверить медиа-минимумы до объявления его production-каталогом.
