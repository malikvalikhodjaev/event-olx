# Telegram-уведомления: короткий ранбук

Сейчас `@malik_valikhodjaev` — личный контакт для обращения «Это ваша страница?». Он не является ботом и не может автоматически получать события Marosim. Внешние авторы получают запросы на исходной площадке; Marosim не видит эту переписку.

Лёгкий вариант до общей базы: оставить ссылки на исходные объявления и личный контакт для подтверждения страниц. Он уже работает без настройки и не обещает несуществующей доставки.

Следующий рабочий вариант: отдельный бот Marosim + общая база сообщений. Владелец создаёт бота у [@BotFather](https://t.me/BotFather) командой `/newbot` и передаёт команде только `@username`. Токен не отправляется в чат, Git или документ: его нужно хранить как секрет серверного окружения. Автор после входа в кабинет нажимает «Подключить Telegram», открывает ссылку на бота и нажимает Start. Сервер получает `chat_id`, связывает его с подтверждённым Marosim-аккаунтом по одноразовому коду и отправляет короткое уведомление о новом запросе со ссылкой на диалог. Полный текст заявки и персональные данные в уведомление не кладутся; в кабинете должно быть отключение уведомлений.

Критическое условие: общий чат на сервере (например, PostgreSQL/Supabase) должен действительно сохранять сообщение до отправки уведомления. Нынешний `localStorage` виден только одному браузеру; бот не узнает о новом сообщении и не сможет доказуемо доставить его другому человеку. Для проверки нужны два разных браузера/устройства, тестовый автор с подключённым ботом и сценарий «сообщение → запись в БД → Telegram → переход в тот же диалог».

Telegram требует, чтобы пользователь сам начал разговор с ботом; одного `@username` пользователя для первой автоматической отправки недостаточно. См. [официальное описание ботов](https://core.telegram.org/bots) и [deep links / Start](https://core.telegram.org/bots/features#deep-linking).
